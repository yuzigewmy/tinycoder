# TinyCoder 三级权限模式

TinyCoder 提供三种持久化权限模式：

- 请求批准（`request_approval`）
- 替我审批（`auto_approve`）
- 完全访问（`full_access`）

默认模式是“请求批准”。模式保存在 `~/.tinycoder/permissions.json`，重启后继续生效。旧权限文件没有 `mode` 字段时会自动使用安全默认值，不需要迁移。

> TinyCoder 当前实现的是应用层权限控制，不是 Codex 使用的操作系统级沙箱。应用层检查可以降低误操作风险，但无法约束 TinyCoder 进程本身或存在漏洞、主动绕过检查的本地程序。

## 使用方式

查看当前模式、模式说明和权限文件路径：

```text
/permissions
```

切换模式：

```text
/permissions request-approval
/permissions auto-approve
/permissions full-access
```

“完全访问”不会在第一次命令时立即启用。确认警告后必须再次输入：

```text
/permissions full-access confirm
```

启动页和 `/status` 都会显示当前权限模式。切换模式后，当前会话中临时允许或拒绝的路径、命令和外部动作会被清空，持久化规则不变。

## 权限矩阵

| 动作 | 请求批准 | 替我审批 | 完全访问 |
| --- | --- | --- | --- |
| 工作区内常规读写 | 允许 | 允许 | 允许 |
| 工作区外普通读取 | 请求用户批准 | 中风险，自动批准 | 允许 |
| 工作区外写入或命令工作目录 | 请求用户批准 | 高风险，回退给用户 | 允许 |
| 常规工作区开发命令 | 允许 | 允许 | 允许 |
| 任意解释器、未知命令、覆盖性命令 | 请求用户批准 | 高风险，回退给用户 | 允许 |
| 破坏性或难恢复命令 | 请求用户批准 | 严重风险，自动拒绝 | 允许 |
| 普通 Web 搜索/抓取 | 请求用户批准 | 中风险，自动批准 | 允许 |
| MCP 只读工具 | 请求用户批准 | 中风险，自动批准 | 允许 |
| 未声明为只读的 MCP 工具 | 请求用户批准 | 高风险，回退给用户 | 允许 |
| MCP 声明的破坏性工具 | 请求用户批准 | 严重风险，自动拒绝 | 允许 |
| 可能包含密钥、Token 或私钥的数据外发 | 请求用户批准 | 风险提升为严重并自动拒绝 | 允许 |

“允许工作区内常规读写”对应 Codex `workspace-write` 的基本交互语义：模型可以在当前仓库完成日常读取和编辑，不会对每个 diff 重复弹窗。路径越界、危险命令和外部系统操作仍由当前模式控制。

## 请求批准

该模式由用户担任审批者：

1. 工作区内常规文件读写直接执行。
2. 工作区外路径、危险命令、Web 和 MCP 动作产生结构化审批请求。
3. 用户可以单次允许、持久允许、单次拒绝或持久拒绝。
4. 非交互模式没有审批界面时，需要审批的动作失败并关闭，不会默认放行。

持久拒绝规则优先于持久允许规则。路径使用规范化后的绝对路径比较，并通过 `Path.resolve()` 处理 `..` 和符号链接逃逸。

## 替我审批

该模式保留与“请求批准”相同的工作区边界，只把原本需要人工处理的请求交给确定性自动审查器。

自动审查器不调用模型，判定结果不会受提示注入影响：

- 低风险、中风险：自动允许。
- 高风险：要求用户批准；非交互环境直接拒绝。
- 严重风险：直接拒绝，不向用户弹出“顺手批准”的选项。
- 审查异常或无法取得交互批准：失败即关闭。

当前严重风险检测包括：

- `git reset --hard`、`git clean`、强制推送；
- `rm -rf`、递归 `Remove-Item`；
- `terraform destroy`、删除 Kubernetes Namespace；
- `DROP DATABASE`、`TRUNCATE TABLE`；
- MCP `destructiveHint=true`；
- 可能包含 API Key、Token、密码、私钥或 SSH/AWS 凭据路径的外发载荷。

当前高风险检测包括：

- `python`、`node`、`bash`、PowerShell 等任意代码执行入口；
- 未知命令；
- `git checkout --`、`git restore --source`；
- `npm publish`；
- 工作区外写入或命令工作目录；
- 没有可靠只读声明的 MCP 工具。

管理器只在内存中保留最近 50 条自动审查记录。记录包含时间、动作类型、风险、决定、理由和作用域哈希，不保存原始命令参数、查询文本或外发数据。

## 完全访问

该模式绕过 TinyCoder 的路径、命令、编辑和外部动作审批，也不执行已保存的允许/拒绝规则。它适用于已经由容器、虚拟机、独立低权限账户或其他外部机制隔离的环境。

需要特别注意：

- TinyCoder 不会创建文件系统沙箱。
- TinyCoder 不会限制网络出口。
- 工作区外文件和用户配置可能被读取或修改。
- 危险命令、破坏性 MCP 工具和可能包含凭据的外发动作不会弹窗。
- 模式会持久化，重启后仍是“完全访问”，直到显式切回其他模式。

## Web 与 MCP

`web_search` 和 `web_fetch` 在发出请求前调用统一的外部动作审批。审批详情只显示目标主机、查询长度等元数据，不把完整查询复制到权限面板。

MCP 工具按描述符注解分级：

- `destructiveHint=true`：严重风险；
- `readOnlyHint=true` 且未声明破坏性：中风险；
- 其他情况：高风险。

MCP 服务器提供的注解只是风险信号，TinyCoder 无法证明远端实现与注解一致。配置恶意或被攻陷的 MCP 服务器仍可能产生风险。MCP 资源和 Prompt 辅助工具也经过外部动作审批。

当前 MCP Server 的启动、能力发现和模型供应商 API 请求属于用户已经配置的运行时基础连接，不按每个请求弹出工具审批。若需要强网络隔离，应在容器、虚拟机或操作系统防火墙中限制 TinyCoder 进程。

## 命令路径检查

命令执行会同时检查：

1. 命令工作目录；
2. 明确的绝对路径、`~` 路径和 `..` 逃逸参数；
3. 命令本身的风险特征；
4. 凭据和私钥特征。

Shell 片段和任意解释器按高风险处理，因为仅靠字符串分析不能可靠枚举其实际文件和网络访问。应用层路径检查不能替代操作系统沙箱。

## 权限存储

`~/.tinycoder/permissions.json` 保存：

- 当前 `mode`；
- 持久允许/拒绝的目录前缀；
- 持久允许/拒绝的命令签名；
- 兼容旧版本的编辑目标规则；
- 持久允许/拒绝的外部动作作用域。

权限模式是当前 TinyCoder 用户级全局设置，不是每仓库设置。审批请求中的“allow once”只在当前进程会话内有效；切换权限模式时会清除这些临时决定。
